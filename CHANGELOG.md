# @omnidotdev/arbor-api

## 0.1.0

### Minor Changes

- [#66](https://github.com/omnidotdev/arbor-api/pull/66) [`319bd39`](https://github.com/omnidotdev/arbor-api/commit/319bd3974b1323168988702129d423826c72083f) Thanks [@coopbri](https://github.com/coopbri)! - Workspace owners and admins can move a repository to another of their workspaces themselves (`transferRepository`). Old links to a moved repository now lead to where it lives: `movedRepository` answers it for anyone who may read the repository, and old clone URLs keep working as before.

- [#59](https://github.com/omnidotdev/arbor-api/pull/59) [`fa5bc9b`](https://github.com/omnidotdev/arbor-api/commit/fa5bc9bb8c55ec411b1b8221c6e0d6a300ccb108) Thanks [@coopbri](https://github.com/coopbri)! - Omni products such as Keystone can now keep your work in a repository your workspace owns. The repository appears in your workspace like any other, and the product only gets write access to that one repository, which a workspace admin can revoke.

- [#64](https://github.com/omnidotdev/arbor-api/pull/64) [`fcaf8e1`](https://github.com/omnidotdev/arbor-api/commit/fcaf8e15dc5464804087dfbecee3860c37c258d3) Thanks [@coopbri](https://github.com/coopbri)! - Omni products such as Keystone can move a repository they manage to another of your workspaces, with its full history, when you are an owner or admin of both. You become its owner in the new workspace, and its old clone URL keeps working for clone, fetch and push.

### Patch Changes

- [#70](https://github.com/omnidotdev/arbor-api/pull/70) [`97006b7`](https://github.com/omnidotdev/arbor-api/commit/97006b76747b52383326781931e68164c1bc7aa8) Thanks [@coopbri](https://github.com/coopbri)! - The production build now runs in production mode, so API errors no longer include internal details and GraphQL runs without development overhead

- [#61](https://github.com/omnidotdev/arbor-api/pull/61) [`aa384af`](https://github.com/omnidotdev/arbor-api/commit/aa384af209430b4782b4dccbf9460bd895898ea4) Thanks [@coopbri](https://github.com/coopbri)! - Agents, stacks, changes, and verification checks now enforce who may create, edit, or delete them: agents belong to the account that registers them (or a workspace owner or admin), and stack, change, and check writes need write access to the repository. An approval now requires write access and cannot come from the pull request's author. Editing a record can no longer move it to another repository, workspace, or owner, and merge queue entries, tester applications, and workspace billing links can only be changed by Arbor itself.

- [#73](https://github.com/omnidotdev/arbor-api/pull/73) [`9af6d9e`](https://github.com/omnidotdev/arbor-api/commit/9af6d9e2444bda59aa3be6a44c69e6cae0ec5c87) Thanks [@coopbri](https://github.com/coopbri)! - Creating and deleting branches, merging pull requests, pull request diffs (merge base and per-file contents), raw file downloads by blob id, and repository imports now always act on the current repository storage. Previously these could read or write an outdated copy, so a merge or new branch could fail or land somewhere it was never served from, and diffs could show stale content. Workspace storage limits are now measured against the real repository sizes, so they are enforced on push. While the git backend is unavailable these requests fail and recover on their own once it is back, and a push to a workspace repository is refused until its storage usage can be checked

- [#71](https://github.com/omnidotdev/arbor-api/pull/71) [`1c0d5f3`](https://github.com/omnidotdev/arbor-api/commit/1c0d5f39442f62aad7989dc5100897fcae084cc7) Thanks [@coopbri](https://github.com/coopbri)! - Clones, fetches, and pushes over HTTPS now always go to the current repository storage. Previously, if the API started while the git backend was still coming up, it kept serving older copies for the rest of its uptime, so recently created repositories failed to clone with "does not appear to be a git repository" and older repositories could return outdated contents. While the backend is unavailable, git requests now fail and recover on their own once it is back

- [#63](https://github.com/omnidotdev/arbor-api/pull/63) [`6d8b8ab`](https://github.com/omnidotdev/arbor-api/commit/6d8b8ab40851da04b7e27c0849ff705979a169ba) Thanks [@coopbri](https://github.com/coopbri)! - Stop writing users' email addresses to the logs: email sends log only the recipient count and message id, by moving to `@omnidotdev/providers` v0.2.0.

- [#67](https://github.com/omnidotdev/arbor-api/pull/67) [`96b559e`](https://github.com/omnidotdev/arbor-api/commit/96b559ee8a55130eef7c3d72e0e07fd24ffe47dc) Thanks [@coopbri](https://github.com/coopbri)! - Fix deleting and renaming a repository, which failed with an unexpected error every time

- [#73](https://github.com/omnidotdev/arbor-api/pull/73) [`9af6d9e`](https://github.com/omnidotdev/arbor-api/commit/9af6d9e2444bda59aa3be6a44c69e6cae0ec5c87) Thanks [@coopbri](https://github.com/coopbri)! - Merging a pull request now only fast-forwards its target branch. When the target has moved on since the branch was created, the merge is refused with "The branch is out of date with its target, update it first and try again", instead of creating a merge commit that silently dropped the target's newer work. Stack merges are fast-forward only too: a change whose base branch has moved on is refused with "The change is out of date with its base branch, update it first and try again" rather than merged over it. Branches with no shared history are refused with "No common ancestor found", for pull request and stack merges alike. Pull request merges now also enforce the target branch's protection rules (required approvals and passing required checks), as stack merges already did. Branch and tag names that would point at a ref of the other kind (such as a tag named `refs/heads/master`) are rejected, so deleting a tag can never delete a branch

- [#73](https://github.com/omnidotdev/arbor-api/pull/73) [`9af6d9e`](https://github.com/omnidotdev/arbor-api/commit/9af6d9e2444bda59aa3be6a44c69e6cae0ec5c87) Thanks [@coopbri](https://github.com/coopbri)! - Deleting a tag now removes only that tag. Previously, deleting `refs/tags/<name>` deleted the branch with the same name instead, and creating a tag created a branch. Workspace repositories now resolve their storage the same way everywhere, so commit, branch, tag, diff, default-branch, rename, merge, and dependency-scan operations work for repositories owned by a workspace whose name differs from the owning member's username

- [#72](https://github.com/omnidotdev/arbor-api/pull/72) [`5496080`](https://github.com/omnidotdev/arbor-api/commit/54960800785740046dafcc8b3a9842423f1963d5) Thanks [@coopbri](https://github.com/coopbri)! - Every plan now includes unlimited collaborators. Workspace repositories on Free, or without a provisioned plan, are no longer limited to 5 collaborators

- [#60](https://github.com/omnidotdev/arbor-api/pull/60) [`dcb7074`](https://github.com/omnidotdev/arbor-api/commit/dcb707434a8d37e7dda686e2bb1a37b95c0fa28e) Thanks [@coopbri](https://github.com/coopbri)! - Creating a repository in a workspace now requires an owner or admin role there, including when an Omni product creates one on your behalf. Workspace membership can no longer be self-assigned through the API, and a repository can no longer be moved to another owner or workspace by editing it.
